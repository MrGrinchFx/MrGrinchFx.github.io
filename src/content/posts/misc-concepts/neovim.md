### Brief History
There is one tool that every developer has once seen before in their programming career, and it's a
relic from the prehistoric days of computing, back when mouses were a novel computer peripheral. In
those days, everything was done on the keyboard, so interfacing with the computer required full
utilization of the keyboard when programming. Thus the birth of vi was introduced in the 1970s by a
graduate student at UC Berkeley: Bill Joy (God Bless that man). 
:::note
There were other reasons for it's invention, such as speed and efficiency compared to other editor
interfaces at the time, but this particular reason sings to my tactile hungry fingers.
:::

### This is stupid. Why would you use a half-baked editor when VS code has all the tools in one package?

To be honest, I shared the same views on the editor as many other developers. Why should I use
something that looks like it was created back when KB floppy disks was still a thing , and when you had to rewind VHS tapes to rewatch a movie (yes I'm young
but I still experienced the latter). And so I went about my undergraduate never even touching it
other than when my professor tried to get us, his students, to try vi out. One of God's unsung
prophets. And let me tell you, that was the most agonizing time of my life.
:::warning
Let's see how many times this editor pisses me off.
:::
I wanted to import some libraries into my program, and lo' and behold, nothing happens. WTF??? This
is already pissing me off! Ok fine, let me just look up how to get it working. Oh shoot, what's normal
mode and insert mode? Why would I ever want to move between one or the other? I should be default in
insert mode because I'm a program writer not a program move-around'er! That pissed me off. Ok whatever,
I got my lil main function up and running, and now I just have to... Wait... where's the exit
button? How do I get back to the shell? I'm pissed off again!!! And thus I shamefully ALT-tabbed to
my web browser and queried the most dreaded question: "How do you exit Vim?" After a quick browse of
the manual, and being enlightened that there is now a Command mode that I now have to share with the
other two, I was able to finally exit the Vim editor.

## Curiosity

Although I spent a majority of undergrad using VS code, I couldn't help but watch content creators
in the space of software development advocate for the use of Vim and its descendant Neovim. It was
advertised as the customizable editor, but most of all... It looked just plain cool to use. Watching
the Primagen fly through the file editing and yanking blocks of text in such a short amount of time
looked so euphoric. In my day to day work, I found that I felt like I was flowing through the
writing of my code when I write a large function all at once. But when it came time to actually edit
the code once it was written, my flow state seemed to dissipate the more I head to cumbersomely
reach for my mouse and aim for the specific line and section of the code I wanted to edit. This felt
unsatisfying and overtime, I began to get bored of programming.
